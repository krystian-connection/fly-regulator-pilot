# Protocol v1 — freeze before test calls

## Question and primary endpoint
Does a persistent measured larval fly-connectome regulator improve a frozen local LLM's adaptation beyond a tuned simple stateful regulator?
Primary outcome: episode return divided by 18 for resources and 10.8 for tools; average tasks equally. These fixed scale constants are upper bounds, not per-episode optimal returns. Primary comparison: paired measured fly minus simple controller. Report signed difference and descriptive 95% paired two-way cluster bootstrap interval. No significance or superiority claim from a point estimate alone.

Topology-specific evidence additionally requires fly improvement over BOTH random and degree-preserving rewired controls, with uncertainty, plus demonstrated action influence and a meaningful persistence ablation. These are secondary diagnostics, not a licence to pick whichever comparator is favourable. A useful negative/underpowered result completes the pilot.

## Data splits and tuning
Whole training episodes use seeds 10000–10039 for each task. Training change ticks [6,12]. Offline validation seeds 20000–20015 with change tick [9]. Validation local-LLM smoke seed 21000, interface seed 11, all seven conditions, both tasks. Test episode seeds 30000–30002 per task with previously unseen change ticks [5,11], crossed with interface/graph seeds 11,29,47. No adjacent-timestep train/test split. Test schedules are unseen exact timings, not a qualitatively different family of change processes.

Every trained condition uses the identical 80 training trajectories (480 decisions) generated by 50% observable heuristic / 50% random exploration. The target is an engineered policy using only observed resources and leaky health-probe history. No latent reliability, future outcome, test observation or hidden optimal action is provided to the controller or used as a readout target. Teacher target is fallible and myopic. All readouts have 16 features plus intercept and three outputs (51 fitted coefficients), training-only feature centering/scaling, ridge fit on training only.

Each simple/random/fly/rewired/reset condition and interface seed receives exactly four candidates: leak in {0.2,0.5}, ridge in {0.01,1}. Select lowest mean squared error on 32 whole offline validation episodes; no LLM calls for fitting. This is a common inexpensive surrogate budget, not exhaustive return-based tuning. `runs/tuning.json` pins final selections. Reset ablation is refitted under its own reset dynamics; disconnection reuses the fitted fly readout but zeroes outgoing advice.

Development record: first balanced 84-call validation completed, exposed a symmetry in resource reward/cost ratios. Before test evaluation, resource values and initial energy were varied with episode seeds; no fly-favouring test outcome was consulted. First code/validation/tuning retained under development_v1 and original validation files. The separate audit then found scoring-only expected regret and unnecessary-action metrics leaking through LLM history. Both earlier validation batches are invalid as performance evidence. Before test, an explicit public history allowlist removes these fields; a final 24-call validation checks alone and fly on both tasks. No readouts or task difficulties were selected from the contaminated LLM performance; candidate selection used the separate offline numerical validation only. Simulated policy difficulty checks over 16 validation seeds show achievable task success and penalize always-recover/inspect policies. No further task changes based on test results.

## Conditions and engineered dynamics
1. Alone: same rules, observations, complete numeric history, action opportunities, neutral recommendation and zero scores; no persistent feature state affects actions.
2. Simple: 16-channel leaky tanh integration plus common output hysteresis.
3. Random: conventional fixed-M directed random recurrent reservoir.
4. Fly: all 2,952 nodes and 110,677 pairs in the supplied measured larval all-all graph.
5. Rewired: three directed double-edge-swap versions, ten accepted swaps per edge, duplicate pairs rejected. Exact in/out degree of each node; incoming strength and normalized weight/sign multiset preserved. This is not a permutation of neuron IDs.
6. Fly_reset: state and recommendation hysteresis reset before each decision; still runs three ticks within a decision; readout refitted fairly.
7. Fly_disconnected: normal fly state runs, but LLM receives exactly the same neutral controller block as alone.

Rate recurrence per reproducible environment tick: x <- (1-leak)*x + leak*tanh(W*x + 0.6*input). Three ticks precede each LLM decision, 18 ticks/episode. No wall-clock-dependent simulation or continuous daemon. Independent episode states start at zero; history and controller memory reset between episodes. Input is 16 engineered numeric features of current resources, remaining time, job values/costs, observed health probes, change flag, failure, progress, task flag, previous action and constant. No language tokens enter recurrence. Same seeded input feature assignment/sign and 16-bucket signed output pooling across graph arms; no anatomical meaning assigned to these ports.

Raw contact counts are normalized by each fly neuron's incoming sum once. Rewired edges retain target-associated weights. Random placement uses the same number of nodes/edges and identical shuffled weight multiset. One final scale shared across all graphs sets the maximum incoming absolute sum across variants to 0.85, guaranteeing contraction with leak <=1. All nonzero recurrent weights are nonnegative, as no transmitter signs are inferred from this source. Engineered signed input/output projections are not biological excitatory/inhibitory annotations.

Remaining mismatches: random in/out degrees and strength placement differ by design; rewiring changes outgoing strengths, autapse count, reciprocal motifs and path structure, while incoming strengths stay exact. Neuron-specific signs are not biologically inferred. Same readout dimension does not match state count between simple (16) and reservoirs (2,952); that is why topology claims depend on graph controls. Common conservative scaling can suppress recurrent topology effects; do not interpret null results as a theorem about all dynamical regimes.

## Action interface and tasks
Every condition sends the same fields: recommendation in A/B/C/NONE and three rounded utility-like scores. A common 0.1 hysteresis retains previous recommendation when the margin is small. The LLM may ignore advice and itself chooses A/B/C. Controller identity, graph name, latent outcomes, seeds and future schedules never appear in the prompt. All previous observations and action outcomes appear, including the same recent-failure and change indicators available to the controller.

Resources: A/B complete work for currently observed reward and energy cost. Insufficient energy produces -2, no work and one violation. C recharges 3 to capacity 6 for -0.1 and completes no work. Hidden schedules change observed values/costs. Tools: A/B succeed for +2 or fail for -0.3, with 0.2 attempt cost and 0.4 switching cost. Each tick supplies independent noisy health probes. C costs 0.4 and reveals precise reliability on the next tick. A precise reading is an actual observation available equally to all conditions taking that action. Latent reliability/outcome arrays are environment-only and used for secondary scoring, never prompt or regulator features.

Each episode consumes exactly six decisions regardless of performance. Invalid/malformed output costs -2 and a violation, with no automatic extra LLM retry. No quit action. Success requires >=4 completed jobs/successful tool uses and zero violations at the full horizon. Expected maximum reward and these success criteria make early quitting/repeated recharge/inspection unprofitable.

## Frozen LLM and budgets
Existing Qwen3.5-4B Q4_K_S through LM Studio 0.4.21+2 at 127.0.0.1:1234. Model checksum in machine.json. Context 4096, full GPU offload, temperature 0, sampling seed 177, max output 32 tokens, constrained action JSON. Explicit Qwen completion prefix closes the reasoning block because the server ignored the chat toggle. This inference mode may limit model capability; it is identical across all arms. No fine-tuning or model changes.

Actual input tokens vary slightly with numeric advice and endogenous histories; same information schema, context cap and output budget, no silent truncation. Report actual prompt/output tokens, latency and failures. Test condition order shuffled with seed 904 to reduce warming/order bias. Local GPU operations are not guaranteed bitwise deterministic; alone/disconnected replay checks expose discrepancies.

Balanced test size chosen after profiling and validation, before test outcomes: 7 conditions x 2 tasks x 3 environment seeds x 3 interface seeds x 6 decisions = 756 calls (126 episodes). Three preflight reservations, including one sandbox-blocked call and one truncated reasoning result; two 84-call validation batches plus a 24-call final sanitized validation; 48 paired causal-probe calls: maximum planned experimental reservations 999. Absolute cap 1,000, enforced by a file-locked append-only reservation ledger plus profile log; reservations are counted conservatively even if a request fails before inference. No automatic retries or call reallocations. Browser exploration is separately tagged, never used to tune or estimate pilot performance.

## Causal probes, outcomes and uncertainty
After test, select 12 fly decision states per task by fixed sorted order (environment seed, interface seed, decision), restricted to decisions 1 and 4 (zero-based 0,3). For each use two calls: original advice and neutral disconnected advice (24 pairs, 48 calls total). Identical public observations, history and model settings within each pair; report action-change fraction. This supplements full-episode disconnected ablation, which can diverge after the first action. Do not equate agreement with advice with causal influence.

Secondary metrics: raw/task-normalized return, success, completed work, violations, total switches, retries after failure, and tool-only unnecessary switches/retries (switch to no better expected utility; retry below best expected alternative). These utility diagnostics use latent reliability solely inside scoring. Recovery lag is decisions from an observed change-containing interval until the next positive, violation-free reward, censored at remaining horizon; this is a coarse recovery proxy, not full re-optimization. Also report expected tool regret, controller wall time, per-call latency/tokens and memory samples.

Bootstrap 10,000 draws, RNG seed 812: resample interface seeds jointly across all tasks and conditions, and environment seeds independently within each task; take the paired mean over the resulting crossed cells. This preserves matched comparisons and does not treat steps as independent. Only three environmental seeds per task and three interface seeds exist, so intervals are descriptive and fragile; the pilot is underpowered and not a population-level confirmatory test. Report all seven conditions, each task separately, all primary/secondary comparator differences, failures and negative findings. Do not select the best seed or the best rewired instance.

## Audit, lock and stopping
Separate audit pass reconstructs reward/cost arithmetic and checks prompt allowlists, common call counts, graph invariants, reset/decay, and ledger consistency. This is a second pass by the same implementation agent, not an independent human review. Unresolved concerns go in HARNESS_REVIEW.md.
`runs/protocol_lock.json` records UTC time and SHA-256 of protocol, experiment, test scripts, graph data, readouts and pinned settings before the first test call. Test runner refuses hash changes or existing output. No edits to frozen execution/scoring/readouts during test; defects requiring changes invalidate the run and must be reported, not silently corrected. Stop after the balanced batch and probes, or at 1,000 reservations, or a fatal infrastructure failure. Preserve partial rows and call logs on failure. Larger runs require user approval.
