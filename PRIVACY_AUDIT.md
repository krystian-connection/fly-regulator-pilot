## Remaining exposure and practical risks

1. **Public identity and contact.** The chosen name and email identify the author and may be indexed, copied or used for spam/phishing. The domain can lead readers to associate the project with an organisation; the contribution statement explicitly asserts no affiliation or sponsorship. The address is kept as instructed, without adding other identity fields.
2. **Study provenance and hardware.** The study date, historical protocol-freeze timestamp, hardware class, model/runtime/dependency versions, scientific seeds and hashes remain. These support interpretation and integrity but reveal some computing context. They contain no hardware serial number, account name, device hostname or home path. Version reporting describes the experimental setup, not necessarily a current installation.
3. **Scientific reputation.** The report states an underpowered, inconclusive pilot, one nonzero primary paired cell, failed tool-task success across all arms, reduced resource success for fly versus alone, contaminated development validations, post-hoc diagnostics and substantial interface/dynamics limitations. It claims neither a living-fly mechanism nor novelty or biological superiority. Same-agent checking is disclosed. Independent methods/code review remains recommended. This audit did not independently revalidate every cited paper or establish novelty.
4. **Rights and reuse.** Exact connectivity redistribution terms remain unresolved, so the archive and all graph/readout binaries remain excluded. MIT scope is limited by the existing notice; documentation/results CC BY 4.0 remains a proposal requiring final approval. Copyright ownership of every possible AI-assisted element is not certified by this audit. The current package supports saved-analysis reproduction, not a self-contained fresh graph/model experiment.
5. **Historical executable code.** Static inspection found the model endpoint restricted to loopback in the supplied code, live-server Host/Origin checks, fixed static routes and an offline replay with connections blocked by its content policy. These are useful restrictions, not a production security assessment. Keep the live inference service local. The historical runner can collect local process IDs and executable paths in future memory logs; do not automatically publish those new logs. Frozen experiment code has not been modified or re-executed for new inference.
6. **Publication permanence.** A public release can be downloaded, mirrored and retained beyond the author's control. Zenodo documents a 30-day owner-deletion window and restricted grounds thereafter; deletion leaves a citation tombstone. GitHub account profiles, commit identities, history, release metadata and any hosted-page analytics are outside this file audit and must be checked when an exact destination is chosen. Publish a fresh repository from the approved allowlist, never this workspace/history. [Zenodo record management](https://help.zenodo.org/docs/deposit/manage-records/).
